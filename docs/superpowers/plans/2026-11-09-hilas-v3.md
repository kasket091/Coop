# Hilas v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Recruiter co-makers, Loan Against Deposit, a transaction history (with voids that reverse the loan), member and admin loan views, a board-members toggle, and the quarterly dashboard.

**Architecture:**
- **Money rules** stay pure and tested in `rules.ts`, `requests.ts`, `accounts.ts` and the new `ledger.ts`.
- **Firebase I/O** stays in `store.ts`.
- **Each member's summary** of 12 monthly savings and interest numbers is worked out from their transactions and written by the admin along with every transaction, so summaries and member screens keep working unchanged.

**Tech Stack:** unchanged (Vite, React, TypeScript, Vitest, Firebase).

**Spec:** `docs/superpowers/specs/2026-11-09-hilas-v3-design.md`

## Global Constraints
- **Loan Against Deposit:** 7% a month. Amount = floor(0.8 × savings ÷ 100) × 100. Allowed only with no unpaid loans and no pending request.
- **Bryan Kevin Tabuan** is a board member and a recruiter, but never one of the 2 over-limit co-makers.
- **Transaction kinds:** `note`, `savings`, `interest`, `principal`, `release`. Voided transactions are ignored by every total.
- **Re-sync** runs once (`settings/migration.v3`) and needs `SYNC` typed to confirm.
- **The admin password** never appears in the repo.

## Review Focus
1. **Voiding a loan transaction that isn't the loan's newest:** refused.
2. **Voiding a `release`:** the request goes back to pending.
3. **A non-founder over their limit:** refused. **A founder over their limit:** needs 2 founders, not Bryan.
4. **Loan Against Deposit with an old-sheet balance above ₱0, or any approved balance:** refused.
5. **Ledger month for a cycle-year mismatch:** clamped (Jan before the cycle, Dec after it).

### Task 1: Pure logic
- **accounts.ts:** `RECRUITS: Record<founderName, recruitNames[]>`, `recruiterOf(name)`, `BOARD` (FOUNDERS + Bryan), `ADMIN_MEMBER_NAME = 'Bryan Kevin Tabuan'`.
- **rules.ts:** `MONTHLY_LOANS.deposit = { rate: 0.07 }`; `depositAmount(saved)`.
- **requests.ts:**
  - `LoanType` adds `'deposit'`.
  - `comakerMode(input)` returns `'none' | 'recruiter' | 'two-founders' | 'blocked'`.
  - `validateRequest` handles the modes and `hasUnpaid`.
  - `loanSnapshot(r)` captures a loan's state before a change.
- **ledger.ts:**
  - `type Txn`
  - `ledgerFrom(txns, cycle)` returns `{ paid[12], interest[12] }`, skipping voided transactions and other cycles
  - `quarterTotals(arr)` returns `[q1, q2, q3, q4]`
  - `newestLiveForLoan(txns, loanId)`
- **Calculator:** "Interest each month" shows the interest only.
- **Tests first** for each item above.

### Task 2: Data layer + rules
**store.ts:**
- `watchMyTransactions`, `watchMemberTransactions`
- `addTransaction` writes the transaction and rebuilds the member summary in one batch
- `voidTransaction(txn, reason)` restores a linked loan from the transaction's snapshot when it is that loan's newest; refuses otherwise
- Loan actions (pay interest, carryover, custom payment, mark paid, approve) write `interest` / `principal` / `release` transactions with snapshots
- `setSheetLoanBalance` writes a `note` transaction
- `createRequest` handles the co-maker modes
- `previewResync()` / `runResync()` build opening transactions from the current sheet, set recruiters, set Bryan as board, add new sheet members, and set the migration flag

**firestore.rules:**
- **transactions:** read by the admin or the owning member; write by the admin only
- **loanRequests create:** 0, 1 or 2 co-maker shapes per the spec

Deploy the rules.
